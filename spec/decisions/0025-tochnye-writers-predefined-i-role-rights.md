# ADR-0025: Точечные writers предопределённых данных и прав роли

- Статус: `accepted`
- Дата: `2026-08-03`
- Задача: [#305](https://github.com/IngvarConsulting/unica/issues/305)

## Контекст

Существующие компиляторы создают объект или роль целиком и небезопасны для
изменения одного предопределённого элемента либо одного права существующей
роли.

## Решение

1. `unica.meta.edit` точечно изменяет `Ext/Predefined.xml` только у `Catalog`,
   `ChartOfAccounts`, `ChartOfCharacteristicTypes` и
   `ChartOfCalculationTypes`; остальные владельцы получают
   `unsupported_operation`.
2. `unica.role.edit` изменяет одно именованное право в существующем
   `Rights.xml`, не пересоздавая остальные узлы роли.
3. Оба writer-а по умолчанию выполняют предпросмотр, до публикации валидируют
   целевой XML и публикуют изменение атомарно. Повторение того же запроса не
   меняет файл.
4. Предопределённый элемент адресуется стабильным уникальным идентификатором `id`; writer не
   генерирует его вместо вызывающего.

## Неграницы

1. Решение не создаёт новые объекты или роли и не заменяет `*.compile`.
2. Решение не делает прочие XML-ресурсы роли редактируемыми.

## Последствия

Точечные плановые изменения больше не требуют ручного XML fallback, а полный
writer остаётся отдельной операцией создания.

## Верификация

- `cargo test -p unica-coder meta role -- --test-threads=1` — точечные
  изменения, идемпотентность, предпросмотр и откат при невалидном XML.
- `tests/ci/test_unica_skills.py` — маршрутизация и предпросмотр нового скилла.
- `tests/ci/test_architecture_registry.py` — регистрация контракта решения.
