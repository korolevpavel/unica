# Точечная правка предопределённых данных и прав роли

- Date: `2026-08-03`
- Status: `draft`
- Decision: `ADR-0025`

## Контекст

`unica.meta.compile` и `unica.role.compile` создают объект целиком. Их нельзя
использовать для изменения существующего `Ext/Predefined.xml` или одного права
в существующем `Rights.xml`: неуказанные узлы будут потеряны.

Предопределённые данные существуют у `Catalog`, `ChartOfAccounts`,
`ChartOfCharacteristicTypes` и `ChartOfCalculationTypes`. Каждый владелец имеет
свой `xsi:type` и свой набор полей элемента, поэтому общий XML-writer не может
подменять типоспецифичные структуры каталоговой.

## Решение

Расширить `unica.meta.edit` операциями `upsert-predefined` и
`remove-predefined` с JSON-описанием элемента. Добавить `unica.role.edit` для
одного точного права существующей роли. Оба writer-а по умолчанию выполняют
предпросмотр, публикуют только точечную замену и валидируют результат до
публикации.

`upsert-predefined` принимает обязательные стабильные `id` и `name`; набор
дополнительных полей проверяется по типу владельца. Неподдерживаемый владелец
или поле завершается `unsupported_operation` без записи.

`role.edit` принимает `RightsPath`, `ObjectName`, `Name` права и булев `Value`.
Он изменяет или добавляет ровно один `<right>`, сохраняя остальные объекты,
RLS, шаблоны и глобальные флаги.

## Последствия

Появляется новый публичный инструмент, поэтому одновременно обновляются ADR,
реестр, схемы MCP, skill и ведомость поверхности. Для каждого из четырёх видов
предопределённых данных добавляется платформенная XML-фикстура до объявления
поддержки формата.
